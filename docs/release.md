# Выпуск Avito Margin Scout

## Что устанавливает пользователь

Единица поставки — расширение для настольного Chrome. Панель работает на компьютере пользователя. Node.js запускает тесты разработчика, Python собирает архив. Для эксплуатации не нужны сервер, Docker, Kubernetes, база данных или переменные окружения.

Поисковые фразы и регион передаются Авито при открытии обычных страниц. История, список товаров, настройки, результаты и адреса для уведомлений хранятся в профиле Chrome. Пользователь может выгрузить результаты в локальный CSV. Удаление расширения может привести к потере локальных данных. В интерфейсе нет восстановления профиля из CSV.

## Проверка и сборка

Из корня репозитория с Node.js 24 и Python 3 выполните команды:

```sh
node avito-margin-scout-v6/tests.js
node --test tests/dashboard-export.cjs
python scripts/package_extension.py
```

В Linux для последней команды можно использовать `python3`. Ожидаемый результат — успешные тесты и `dist/avito-margin-scout-<version>.zip`. Сборщик читает версию из манифеста, проверяет описание и упаковывает исполняемые файлы, HTML, CSS и иконки. Распакованный архив должен содержать `manifest.json` на верхнем уровне. Старый ZIP из истории репозитория для релиза собирать заново не требуется.

На push и pull request GitHub Actions выполняет синтаксическую проверку JS, оба тестовых набора и сборку. Тот же workflow можно запустить вручную. Скачайте артефакт успешного запуска для выбранного коммита. Если GitHub обернул его во внешний архив, извлеките внутренний ZIP расширения. Для воспроизводимости выпуска сохраните SHA коммита и SHA-256 отправленного ZIP. В PowerShell контрольную сумму показывает `Get-FileHash dist/*.zip -Algorithm SHA256`.

## Приёмка пакета

1. Распакуйте **собранный ZIP** в отдельный каталог. В чистом профиле настольного Chrome откройте `chrome://extensions`, включите режим разработчика, загрузите этот каталог. Проверьте версию, иконку, открытие панели и отсутствие ошибок расширения.
2. Проверьте пустой город и режим «Только мои» с пустым списком. Панель должна объяснить, какое поле заполнить. Добавьте одну модель и убедитесь, что после повторного открытия список сохранился.
3. Проведите ручной поиск известной модели в одном городе. Сопоставьте в нескольких карточках название, конфигурацию, цену и регион с исходной страницей. Если сайт ограничивает доступ, проверьте сообщение и остановку. При подтверждённой блокировке завершите приёмку этого сценария.
4. Экспортируйте выборку, сравните цены и число подходящих строк с фильтрами панели. Переключите город и убедитесь, что карточки предыдущего города исчезли. При наличии нового подходящего результата проверьте клик по системному уведомлению.
5. Обновите тестовую установку в той же папке через кнопку перезагрузки расширения. Проверьте список моделей, историю и сохранённый регион. Выполните новый поиск для пересчёта старых результатов.

## Слабые места и условия публичного выпуска

Аудит исходной версии 6.0.0 обнаружил смешение поколений консолей, интерпретацию некоторых текстовых полей CSV как формул и описание в манифесте на 150 символов при ограничении магазина в 132. Эти случаи исправлены в 6.0.1. Расчёт по объявлениям по-прежнему зависит от качества названий и состояния товаров. [Требования к пакету](https://developer.chrome.com/docs/webstore/prepare)

| Приоритет | Наблюдение и последствие | Что проверить или изменить |
| --- | --- | --- |
| Высокий | В `engine.js`, `financials` сохраняет прежний ручной ориентир после очистки поля. Для товара за 1 000 ₽ без аналогов ручной ориентир 10 000 ₽ продолжает давать прибыль после очистки. | Пересчитывать ориентир из текущего ввода или `marketReference`, проверять оба перехода в UI и CSV. До исправления повторять поиск после изменения ручной цены. |
| Высокий | Каждый клик в `popup.js` создаёт новую панель. В `dashboard.js` каждая панель читает собственную копию истории и затем записывает её целиком. Запоздалая запись способна потерять результаты другой панели. | На пилоте использовать одну панель. До массового выпуска проверить две одновременно открытые панели и исключить конкурирующие записи. |
| Средний | В `dashboard.js`, `run` записывает текущую выборку и после прерывания. CAPTCHA или неверный регион на первой странице могут заменить последнюю удачную выдачу пустой. | После удачного запуска проверить прерывание первого и последующего запросов. Разделить состояние попытки и последние полные результаты. |
| Средний | В `scrapeVisibleCards` разбор зависит от DOM Авито. В `run` пустая выдача и ошибка чтения попадают в общий счётчик. Поломку селектора трудно отличить от отсутствия предложений. | Добавить обезличенные HTML-фикстуры карточек и раздельные статусы ошибок. Проверить работу на актуальной выдаче вручную перед выпуском. |

На пилоте собирайте версию расширения и Chrome, режим, шаги и текст ошибки. Панель пишет ошибки поиска и хранилища в свои DevTools, фоновый обработчик уведомлений — в консоль service worker на `chrome://extensions`. Перед передачей диагностики убирайте личные запросы и адреса объявлений.

## Рекомендуемый канал распространения

1. Для пилота используйте **Private** в Chrome Web Store с группой тестировщиков. Загрузите ZIP из проверенной сборки через аккаунт издателя, заполните карточку, сведения о данных и обоснование разрешений. Укажите доступ к вкладкам, чтение видимых карточек на Авито, локальное хранение и уведомления. Проверьте условия использования площадки и требования магазина перед отправкой на проверку. [Публикация расширения](https://developer.chrome.com/docs/webstore/publish)
2. После закрытия дефектов и приёмки измените видимость той же карточки на **Unlisted** для установки по ссылке или **Public** для поиска в магазине. Использование существующей карточки сохраняет ID расширения у пилотной группы. Установка из магазина может иметь другой ID, чем локальная распакованная копия. [Обновление и смена канала](https://developer.chrome.com/docs/webstore/update)
3. Для исправляющего релиза соберите проверенный код с версией выше опубликованной и загрузите в ту же карточку. При возврате к предыдущей реализации сначала проверьте её на данных, сохранённых новой версией. Сохраните предыдущий рабочий коммит и ZIP для сравнения и тестов. [Требования к обновлению](https://developer.chrome.com/docs/webstore/update)
